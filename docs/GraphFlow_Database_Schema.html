GraphFlow — Database Schema

Creative workflow intelligence and billable-hour optimization. Relational schema of the implemented system on PostgreSQL 16: employees' work activity is recorded as events, reconstructed into time intervals, turned into timesheets, approved by managers and billed per project.

23tables
4functional areas
PostgreSQL 16database
RLStenant isolation
How to read the tables
PK primary key   FK → table foreign key   UQ unique
All ids are UUID · timestamps are timestamptz (UTC) · durations are whole seconds · money is DECIMAL.
Every tenant table also has organization_id (FK → organizations) and Row-Level Security.

6. Access rules (enforced by PostgreSQL Row-Level Security)

RoleCan readCan change
EmployeeOwn activity, sessions and timesheetsOwn profile (not role, team, status or email); own draft timesheets
Team leadActivity of own team members—
Project managerProjects they manage and activity on themEdit own projects, assign members, review timesheets of own projects (never own)
Org adminWhole organizationUsers, teams, tools, settings; review any timesheet except own
Worker (system)One organization at a timeNormalized events, sessions, collaboration links
Database-level protections: the audit log and billing adjustments are append-only; approved timesheets cannot be changed; nobody can approve their own timesheet; employees cannot change their own role; the application connects with a restricted role that cannot bypass these rules.
